📄 index.html — 스페인어 홈페이지

무슨 파일인가: 손님이 처음 보는 메인 페이지. 인스타 프로필 링크, 광고, DM에 이 URL을 보내면 됨.

디자인: 모바일 우선(스마트폰에서 먼저 예쁘게 보이게), 오렌지(#F97316) + 틸(#0D9488) + 크림(#FFF7ED) 따뜻한 톤. 외부 라이브러리 없이 순수 HTML/CSS/JS로 제작 → 로딩 빠르고 유지보수 쉬움.

페이지 구성 (위→아래 순서):

  • 네비게이션 바 — 상단 고정. 모바일에서는 햄버거(☰) 메뉴로 바뀜. 각 섹션으로 부드럽게 스크롤.
  • Hero 섹션 — 첫인상. "Vive Corea como un local, con tu guía en español" 큰 제목 + CTA 버튼. 3개 통계 뱃지(100% 스페인어 / 프라이빗 / 맞춤형).
  • Por qué (왜 나와 함께?) — 손님의 4대 불안(언어·길찾기·안전·관광객코스)을 카드 형태로 해결. 아이콘 + 짧은 카피.
  • Qué incluye (뭐가 포함?) — 탭 UI로 서울/부산/특별체험 전환. 각 도시별 4개 활동 카드. 서울: 경복궁·북촌·한강·광장시장. 부산: 해운대·스파랜드·블루라인파크·감천.
  • Cómo funciona (어떻게 진행?) — 3단계 원형 넘버링: ①번호 남기기 → ②WhatsApp 예약링크 → ③Zoom 상담 후 맞춤투어.
  • Precios (가격) — 6시간 $190 / 8시간 $210 (인기 뱃지) + 추가 시간당 $30. 현금 결제.
  • FAQ — 아코디언(접었다 펴기) 7개 질문: 안전, 결제, 언어, 식단, 프라이빗, 포함사항, 서울+부산 결합.
  • Testimonios (후기) — Placeholder 3개 (마리아/후안/라우라). 별 5개 + 후기 텍스트 + 국가. → 실제 후기로 교체 필요
  • CTA 폼 — 틸 배경 위에 흰색 카드. 이름 + 전화번호(국제형식) + 동의 체크박스. 제출하면 gracias.html로 이동.
  • Footer + WhatsApp 플로팅 버튼 — 오른쪽 하단 초록 원형 버튼. 클릭하면 WhatsApp 대화 시작.

보안 장치:

  • 허니팟 — 숨겨진 "website" 필드. 사람은 못 보지만 봇은 자동으로 채움 → 채워져 있으면 제출 무시.
  • 전화번호 검증 — +로 시작, 8~15자리 숫자만 허용. "+52 55 1234 5678" 같은 국제 형식.
  • 동의 체크 — 체크 안 하면 제출 불가.

SEO: title, meta description, keywords, Open Graph (카카오톡/인스타에서 공유할 때 미리보기), JSON-LD 구조화 데이터 포함.

🔄 리드 캡처 흐름 (폼 제출 → CRM)

손님이 폼을 제출하면 이런 일이 일어남:

1. 손님이 index.html 폼에 이름+전화 입력, "Quiero mi tour" 클릭 2. JavaScript가 허니팟·전화형식·동의 검증 3. fetch()로 addLead.gs (Apps Script)에 POST 전송 → payload: { token, action:"addLead", lead: { name, phone, consent, source:"homepage" } } 4. addLead.gs가 토큰 확인 → clientes 시트에 새 줄 추가 → source="homepage", stage="sns", channel="홈페이지", review="검토필요" 5. notifyNewLead()로 이메일 알림 전송 (내가 제일 먼저 아는 방법) 6. 손님 브라우저는 gracias.html로 이동 ("곧 WhatsApp 드릴게요") 7. 내가 CRM에서 확인 → WhatsApp으로 Calendly 링크 전송 (수동)

📜 addLead.gs — Apps Script 리드 캡처

무슨 파일인가: Google Apps Script에 붙여넣어서 배포하는 서버 코드. 홈페이지 폼에서 오는 POST 요청을 받아서 구글시트에 한 줄 추가.

핵심 설계 원칙: Append-only (추가만 가능). 이 스크립트로는 기존 데이터를 읽거나 수정하거나 삭제할 수 없음. 혹시 URL이 유출되더라도 데이터 유출·변조 불가.

어떻게 동작하나:

  • doPost(e) — POST 요청 수신. JSON 파싱 → 토큰 확인 → 허니팟 체크 → 전화 검증 → 시트 append.
  • buildRow(headers, lead) — 시트의 헤더 행을 읽어서 올바른 열 순서로 데이터 배치. 헤더가 바뀌어도 자동 적응.
  • doGet() — GET 요청에는 "status: ok"만 반환. 데이터 노출 없음.

배포 방법: script.google.com → 코드 붙여넣기 → CONFIG.SHEET_ID와 CONFIG.TOKEN 설정 → 배포 > 웹 앱 → URL 복사 → index.html에 입력.

📋 itinerary-es.html — 맞춤 일정표

무슨 파일인가: 각 손님한테 보내는 개인화된 일정표. URL에 파라미터를 넣으면 해당 손님 이름, 날짜, 도시에 맞게 자동으로 내용이 바뀜.

어떻게 쓰나: CRM에서 손님 정보를 URL에 넣어서 WhatsApp으로 보냄. 손님은 링크 클릭 → 예쁜 일정표 확인 → "PDF 저장" 버튼으로 저장.

URL 파라미터:

  • name — 손님 이름 (필수)
  • date — 투어 날짜 (필수, YYYY-MM-DD)
  • hours — 투어 시간, 6 또는 8 (기본 8)
  • cities — 도시들, 쉼표 구분 (seoul 또는 seoul,busan)
  • meet — 미팅 장소
  • notes — 특별 노트 (식단, 관심사 등)

구성: 헤더(이름+브랜드) → 정보바(날짜/시간/미팅포인트) → 특별노트(노란박스) → 타임라인(시간대별 블록, 활동명+설명+태그) → 중요사항(체크리스트) → PDF 버튼.

보안: URL에 가격·전화번호 절대 넣지 말 것. URL은 브라우저 히스토리에 남고, 공유될 수 있음.

🧾 recibo-es.html — 영수증/컴프로반테

무슨 파일인가: 투어 끝나고 손님한테 보내는 영수증. 금액이 자동으로 계산됨.

가격 자동계산 로직:

  • baseHours=6 → 기본 $190 USD
  • baseHours=8 → 기본 $210 USD
  • extraHours=N → N × $30 USD 추가
  • 예: 8시간 + 2시간 추가 = $210 + $60 = $270 총액

영수증 구성: 헤더(PAGADO 뱃지) → 고객정보(이름/날짜/시간) → 서비스 내역 테이블(기본+추가) → 총액 → "현금 수령" 초록 박스 → 브랜드 푸터 → PDF 저장.

영수증 번호: 날짜 + 랜덤 4자리로 자동 생성 (예: REC-101525-A3KF).

📜 form-sync.gs — Google Form → CRM 동기화

무슨 파일인가: Google Form(설문지) 응답이 들어오면 자동으로 clientes 시트에 동기화하는 Apps Script.

왜 필요한가: 구글폼으로도 리드를 받는 경우, 홈페이지 리드와 같은 CRM 시트에서 통합 관리하기 위해.

핵심 기능:

  • 전화번호 dedup — 같은 전화번호가 이미 있으면 새 줄 안 만들고, 기존 줄의 빈 칸만 채움.
  • 이메일 폴백 — 전화번호 없으면 이메일로 매칭.
  • 전화번호 정규화 — 공백, 대시, 괄호 제거. "+52 (55) 1234-5678" → "+5255 12345678".
  • initialBackfill() — 처음 한 번 실행하면 기존 폼 응답 전체를 CRM에 동기화.
  • onFormSubmit 트리거 — 새 응답이 들어올 때마다 자동 실행.

칼럼 매핑: FORM_TO_CRM_MAP 객체에서 폼 질문 → CRM 필드 매핑. 실제 폼에 맞게 수정 필요.

📧 lead-notify.gs — 이메일 알림

무슨 파일인가: 새 리드가 들어오면 내 이메일로 알림 보내는 함수.

어떻게 동작하나: notifyNewLead(lead)를 호출하면 MailApp으로 예쁜 HTML 이메일 발송. 이름, 전화, 소스, 시간(KST) + Calendly 링크 포함.

사용법: addLead.gs의 doPost에서 append 성공 후 notifyNewLead(lead) 한 줄 추가. 또는 form-sync.gs에서도 호출 가능.

제한: Gmail 무료 = 하루 100통 / Workspace = 1,500통. 솔로 운영이면 충분.

🐍 calendly-sync.py — Calendly 예약 → CRM 연동

무슨 파일인가: Calendly에서 손님이 상담을 예약하면, webhook으로 알림이 오고, CRM 카드를 자동으로 생성/업데이트하는 Python Flask 서버.

왜 필요한가: Calendly 예약 → 자동으로 CRM에 기록 + 미팅ID 저장 (나중에 Zoom 녹음이랑 매칭용).

흐름:

1. 손님이 Calendly에서 30분 상담 예약 2. Calendly가 이 서버로 webhook POST 전송 3. 서버가 이름, 전화번호, 이메일, 미팅시간 추출 4. CRM에 POST → 전화번호로 기존 카드 매칭 or 새 카드 생성 5. stage="consulta", meetingId+startTime 저장

배포: Flask 서버를 ngrok이나 클라우드에 올리고, Calendly Dashboard에서 webhook URL 등록. 키는 .env에.

🤖 zoom_to_crm.py — Zoom 녹음 → AI → CRM 자동 입력 (545줄)

무슨 파일인가: Zoom 상담이 끝나면, 녹음에서 자막을 가져와서 AI(Claude Haiku)가 손님 정보를 자동 추출 → CRM에 입력하는 완전 자동화 파이프라인.

왜 필요한가: 30분 상담에서 손님이 말한 이름, 전화, 여행날짜, 관심사, 식단제한 등을 수동으로 CRM에 옮기는 건 시간 낭비. 이걸 AI가 자동으로 해줌.

전체 흐름:

1. Zoom API에서 최근 24시간 녹음 목록 가져오기 (OAuth 인증) 2. 각 녹음의 VTT 자막 파일 다운로드 → 자막 없으면? Whisper(로컬 STT)로 음성→텍스트 변환 (폴백) 3. 자막 텍스트를 Claude Haiku에 전송 + 시스템 프롬프트 → "이 스페인어 상담에서 손님 정보를 JSON으로 추출해줘" 4. AI가 CRM 스키마에 맞는 JSON 반환 → { name, phone, origin, cities, interests, diet, hours, ... } 5. 칩/태그 필드 유효성 검증 (잘못된 값 제거) 6. Calendly 예약과 매칭 (미팅ID 또는 시작시간 ±15분) → 매칭되면 전화번호·이름 보강 7. Apps Script로 CRM upsert (review="검토필요") 8. 처리한 녹음 ID를 로컬 JSON에 저장 (다음 실행 시 건너뜀)

AI 시스템 프롬프트 핵심 규칙:

  • 대화에서 명시적으로 언급된 것만 추출 — 추측 금지.
  • 모르는 필드는 빈 문자열 "" 또는 빈 배열 [].
  • 칩 필드는 정해진 한국어 옵션만 사용: 서울/부산, 커플/가족/친구/혼자, 봄/여름/가을/겨울 등.
  • JSON만 출력 — 설명 텍스트나 마크다운 금지.

Cron 설정: 15분마다 자동 실행. 이미 처리한 녹음은 건너뜀(멱등성).

필요한 키: ZOOM_ACCOUNT_ID, ZOOM_CLIENT_ID, ZOOM_CLIENT_SECRET, ANTHROPIC_API_KEY

🎬 VOD 회원 영역 — Supabase + Stripe (테스트 모드)

무슨 시스템인가: 투어 영상을 유료로 판매하는 회원 전용 페이지. 로그인 → 결제 → 영상 시청까지 테스트 모드로 끝까지 동작.

왜 이 구조인가: S3 정적 호스팅만으로는 인증·결제가 불가능. 그래서 VOD 부분만 Supabase(인증+DB) + Stripe(결제)를 사용.

4개 파일 구성:

① vod/index.html (1040줄) — VOD 매장 프론트엔드

  • 비로그인 상태: 이메일 입력 → "매직링크 보내기" → 이메일에 링크 클릭 또는 6자리 OTP 입력. 비밀번호 저장 없음.
  • 로그인 후 미구매: 영상 썸네일에 자물쇠 아이콘 + 가격 + "Comprar acceso" 버튼 → Stripe Checkout으로 이동.
  • 로그인 후 구매완료: 자물쇠 해제 → 썸네일 호버시 재생 아이콘 → 클릭하면 모달 비디오 플레이어.
  • 테스트 모드 배너: 상단에 노란 바 "MODO DE PRUEBA — 카드 4242 4242 4242 4242".

② vod/supabase-schema.sql — 데이터베이스 스키마

  • profiles — auth.users와 자동 동기화 (트리거). 이메일 저장.
  • videos — 영상 카탈로그. 제목, 설명, 썸네일URL, 영상URL, 가격(센트), Stripe Price ID.
  • purchases — 구매 기록. user_id + video_id + stripe_session_id(UNIQUE, 중복 방지).
  • videos_with_access — 보안 뷰. 구매한 사용자에게만 video_url 반환, 안 산 사람에게는 NULL.
  • RLS(Row Level Security) — 각 사용자는 자기 프로필과 자기 구매만 볼 수 있음.
  • 테스트용 영상 3개 시드 데이터 포함.

③ vod/functions/stripe-webhook.js — 결제 완료 처리

  • Stripe가 결제 완료되면 이 함수를 호출.
  • 서명 검증(위조 방지) → metadata에서 user_id + video_id 추출 → Supabase purchases 테이블에 기록.
  • 중복 체크: 같은 stripe_session_id면 건너뜀.
  • Vercel / Netlify / Express 3가지 배포 방식 지원 (파일 하나에 다 들어있음).

④ vod/SETUP.md — 설정 가이드

  • Supabase 프로젝트 생성 → SQL 실행 → 키 복사 단계별 안내.
  • Stripe 테스트 상품·가격 생성 → Price ID를 DB에 업데이트.
  • 테스트 플로우: 가입 → 매직링크 → 4242 카드 결제 → 영상 접근.
  • 라이브 전환 체크리스트 — 테스트→실제 전환 시 바꿀 것들 목록.

결제 흐름:

1. 손님이 VOD 페이지 방문 → 이메일로 로그인 (매직링크) 2. Supabase에서 videos_with_access 뷰 조회 3. 미구매 영상: 자물쇠 + "Comprar acceso" 버튼 4. 클릭 → 서버리스 함수가 Stripe Checkout 세션 생성 5. Stripe 결제 페이지에서 카드 입력 (테스트: 4242 4242 4242 4242) 6. 결제 완료 → Stripe webhook → stripe-webhook.js 호출 7. purchases 테이블에 기록 → 사용자의 video_url 접근 허용 8. 손님 돌아옴 → 자물쇠 해제 → 영상 재생 가능
